# Notes: Expo review

## Where the findings came from

A read-only review on 2026-10-04 against the official Expo agent skills (Claude Code plugin `expo@claude-plugins-official`, v1.13.6): `expo-data-fetching`, `expo-router`, `expo-project-structure`, `expo-overview`, `expo-animation`, `expo-design-system`, `expo-native-ui`, `expo-module`, `expo-upgrade`. Each finding in `MAIN.md` was read in the code; the top bugs (back handler, splash hang, poll overwrite, `useNow(1000)`, `ActionWorker` race) were checked a second time by hand. Line numbers are from commit `87a2f72` and will drift: find the code by the names given.

`npx expo-doctor` passed 20 of 21 checks; the one failing was the version alignment fixed in step 6.

## Decisions (2026-10-04)

- **Scope:** all four groups (bugs, JS-thread load, hygiene, accessibility and polish).
- **Overlap with `implan-instant-taps`:** this plan owns the JS-thread load fixes (`useNow` split, async notification calls, unused native packages, `signal`, retry). They're wins whatever the device tap log shows. Press feedback stays in instant-taps step 3 (native ripple). This plan only adds feedback to tappables that have none and caps the press scale at 0.97. Leave a pointer in `implan-instant-taps/NOTES.md` when step 5 lands, so its step 2 knows.
- **Sheet keyboard:** `react-native-keyboard-controller` (what the skill names), installed with `npx expo install`. It's a new native dependency, so it needs a clean prebuild.
- **Sheet handle:** keep it and make it work, with drag-to-dismiss and a slide-in/out spring that respects Remove animations.
- **Unused native packages:** remove all five: `expo-symbols`, `expo-glass-effect`, `@expo/ui`, `expo-device`, `expo-web-browser`. Keep `expo-linking` and `expo-constants` (peers of `expo-router`).

## Left out on purpose

- **AsyncStorage → `expo-sqlite/localStorage`** (the skill lists AsyncStorage as deprecated). Moving the persisted cache needs a data migration; not worth it now.
- **`usesCleartextTraffic: true`.** It's likely deliberate, since Baby Buddy runs plain HTTP on the home network. Revisit only if the hosts become fixed.
- **Help as a modal route, and moving `ConnectionSheet` out of `settings.tsx`.** Low value. The structure skill says its layout rules apply to new projects.
- **Moving the inline sheets to `formSheet` routes.** The inline sheets are part of the ring design.

## Findings while building

- **Step 1.** Unknown 4xx (and 401) now: 401 → `unauthorized`, every other status that isn't 400 / 403 / 404 → `server` (its toast reads "Baby Buddy refused the change (server)", generic enough, so no new kind). Every read takes `{ signal }` as its last argument. React Native's `AbortSignal` has no `any` / `throwIfAborted` and may have no `reason`, so `request` listens on the caller's signal and aborts its own timeout controller; a cancelled call rethrows the abort (`name: 'AbortError'`), never a `BabyBuddyError`. TanStack ignores what a cancelled `queryFn` throws anyway. `collect` pages by its own offset and dedupes by id.
- **Step 2.** Bug 5's single source: the `entries` query now fetches sleeps from `PREDICTION_DAYS` back (the old `sleeps` query and `predictionSleeps` are gone); everything else that reads `entries.sleep` is window-scoped, so the longer list changes nothing on screen. Guesses are recognised by TanStack's own `manual` flag on the cache's `success` action (`setQueryData` sets it, a fetch clears it), tracked in `createQueryClient` (`src/lib/query.tsx`), instead of negative ids. Polls are held by `holdPolls()` (`features/dashboard/writes.ts`), taken in every dashboard write and released before its refresh; the polling hooks read it with `usePolling`. After a write, `past` / `days` are only invalidated and refetched if on screen (`meta.showing` for `past`, `isActive()` for `days`); `usePastEntries` refetches an invalidated `past` when its page opens. `settings` has `staleTime: Infinity` and is dropped when the session (`persistKey`) changes, since sign-in writes settings without invalidating. `history`, `latest`, `entry` keys were dead and are gone from the refresh.
- **Step 3.** `useNow` is one shared clock (a `setTimeout` just after each whole second while anything listens) read through `useSyncExternalStore`, quantised per interval, so `useNow(60_000)` re-renders on the minute and every `useNow(1000)` shows the same second. The dashboard ticks per minute; the ring's `centre` prop is now `(now) => CentreText`, worked out by a `Centre` leaf on its own 1 s tick. Checked on the web image with a temporary render counter and spec (both removed): 0 dashboard renders in 6 s with a sleep running, centre and tile read the same `0:0N` every second. The running sleep's arc and the now hand move per minute (a quarter degree), not per second. The Android emulator check is folded into step 6's release build. `e2e/tests/errors.spec.ts` now expects 5 persisted queries (the `sleeps` query is gone).
- **Step 4.** The dashboard's Back handler sits in `useFocusEffect`. Storage failures: `SessionProvider` ends `signedOut`, `ThemeProvider` uses `DEFAULT_SETTINGS`. `ErrorScreen` (`src/components/ErrorScreen.tsx`) is the `ErrorBoundary` of `(main)/_layout.tsx` and, wrapped in its own `ThemeProvider` (it replaces the whole layout), of `_layout.tsx`; it also hides the splash. `+not-found` must redirect by session: a `<Redirect href="/">` while signed out stays on the unknown URL with a blank page, since `/` is behind the signed-in guard, so it sends signed-out visitors to `/onboarding`. With `anchor: 'index'`, a reloaded `/child/3`'s `router.back()` would land on the dashboard while its link says "Settings", so the child screen now uses `router.dismissTo('/settings')`. `goBack` in `ui.tsx` is unchanged (the anchor makes `canGoBack()` true after a reload). New `e2e/tests/shell.spec.ts`: unknown path signed in / out, reload + Back for Settings, Recent days and a child, unreadable storage → onboarding. Error screen checked with a temporary throw (removed): themed, Try again recovers.
- **Step 4, emulator.** Release build on `emulator-5554`: cap to the past window, Settings, one Back → the dashboard (still on the past window), a second Back → now.
- **Step 5.** `show`, `keepOnly`, `showReminder`, `keepOnlyReminders`, `liveUpdates` are `AsyncFunction`s; `syncNotifications` is async and awaits each call in turn (a late `show` after the next sync's `keepOnly` would bring a notification back), and `refresh.ts` awaits it. `ActionWorker`: an `AtomicBoolean` starts the task once, the context is checked again after adding the listener (and `host.start()` only runs when it's still null), a 60 s timeout (`TIMEOUT_MS` + 30 s) ends the work as a failure, and every ending (`finish`) calls `Notifier.restoreIfPending`. Recovery is native-only: `post` keeps the last full content JS drew per tracker and child (`content:<tracker>:<child>` in the `molly.notify` prefs, dropped by `keepOnly`), `showPending` marks its notification with an extra, and a notification still marked pending is reposted from that content (or cancelled if there is none). The receiver now passes `tracker` to the worker. `colorOf` wraps `parseColor` (fallback grey). Emulator checks on the release build: a Stop tapped with the process killed (`kill -9` as root, `am kill` didn't stop it) runs in under a second (worker SUCCESS, sleep notification gone, Vitamin D reminder posted); with a temporary build that never started JS and a 5 s timeout (reverted), "Stopping…" came back as "Sleeping · Stop" with the chronometer unbroken; the centre and the Stop tile showed the same second; Settings shows "Live updates are off" through the async call. A process killed mid-task leaves the pending line until WorkManager reruns the unfinished work on the next start.
- **Step 6.** Removed `expo-symbols`, `expo-glass-effect`, `@expo/ui`, `expo-device`, `expo-web-browser` (no import, plugin or config anywhere). `npx expo install --fix`: expo 57.0.26, expo-router 57.0.24, expo-camera 57.0.6, expo-constants 57.0.20, expo-linking 57.0.11. Added `react-native-keyboard-controller` 1.21.9 (wired in step 7). `react-native-android-widget` pinned to `0.22.1`; the patch applies on install. `expo install --check` clean, `expo-doctor` 21/21. Clean `pnpm android:release` installed on the emulator: dashboard loads, a lock-screen Stop (app alive) saves the sleep, a widget Wet saves the change and draws "Saved". The `packages/api` integration tests in `pnpm check` reset the test child, so emulator data logged before a check is gone after it (not an app bug).
- **Step 7.** `Sheet` (`src/components/sheet.tsx`): the scrim fades and the sheet springs up (`SlideInDown.springify().duration(300).dampingRatio(0.8)`) as Reanimated layout animations, so it also slides out (`SlideOutDown`, 200 ms ease-out) when its parent unmounts it, whoever closed it; all with `ReduceMotion.System`, and no slide at all under `useReducedMotion`. The drag lives on an inner layer (`translateY` shared value), the pan only on the handle and header (`GestureDetector`), so content scrolling never closes it; it settles in `onFinalize` (closes past 35 % of the sheet's height or on a flick projected there, spring with the finger's velocity; springs back otherwise), and the scrim fades with the drag. Keyboard: `KeyboardProvider` at the root, the sheet lifted by `useReanimatedKeyboardAnimation` minus the nav bar inset (the old `Keyboard.addListener` state is gone). TalkBack: `BehindSheet` wraps a screen's body with `importantForAccessibility="no-hide-descendants"` while that screen's own sheet is open (dashboard, Settings, and the toast provider for Adjust time); a shared flag would have hidden the open sheet too, since the toast provider wraps every screen. Checked: full e2e suite green on the web (155); on the emulator the Add sheet opens and lands right, a short slow drag springs back, a long drag closes, scrolling the Today sheet doesn't close it, and the compressed accessibility tree (what TalkBack reads) holds only the scrim and the sheet. The emulator has a hardware keyboard and Gboard only shows its floating toolbar there, so the keyboard lift is for a physical phone.
- **Step 8.** Press scales below 0.97 (0.92 / 0.94 / 0.95 / 0.96) are now 0.97; `Pressable` still drops them under Remove animations. Pressed states: `Segment` options and the Add sheet's unpicked kind chips get `active:bg-line`; `ToggleRow`, "Not now", the key help link and the toast's "How to fix" get `active:opacity-70`. `Segment` options are `min-h-12` (48) without the 4 px slop. Timers are spoken in minutes (`spokenDuration`): the running tile's label, and the ring centre through a `spoken` field on what `centre(now)` returns (sleeping, feeding). The Add button has `accessibilityHint={problem}`. Skeleton uses `.get()` / `.set()`. Tokens: `text-caption` (13), `text-label` (15), `text-title` (17), size only; the 18 / 10 px corners became `rounded-mock` / `rounded-mock-sm`, fixed values rather than theme corners, because they draw things outside the theme (the theme picker's cards, Android's notification in the Lock screen sheet) and no theme corner is 18 px, so mapping them onto `--rc` and friends would have changed some themes. Checked on the web: a caption computes to 13 px, a Segment option is 48 px high. Specs that matched `m:ss` in labels now match minutes (`accessibility`, `ring`, `running`, `add-entry`).
- **Step 9.** Bug 1 checked on the web with a temporary spec (removed): a Start write held 13 s, tapped 20 s after load so the 30 s poll falls inside it; the tile stayed "Stop sleep" throughout and only the server check and the refetches after the write read the timer. A control run with the hold switched off saw one more timer read but no visible flip either, so this shows polls pause during a write, not that the old code flipped on the web. Emulator look pass: Terminal at night (Settings, dashboard), the Theme sheet, Classic; emulator set back to Molly Classic / Follow the phone afterwards.
