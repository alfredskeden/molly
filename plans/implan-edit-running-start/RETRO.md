# Retro

## 2026-09-25: Edit a running timer's start (steps 1–2, Android release installed)

| Category | Details |
|---|---|
| **Went well** | • Probing the live API before writing the rule (step 1's "check first") changed the design cheaply: feedings got an earliest time too.<br>• A small two-step plan with a decisions table left no open questions mid-build; the 5 new Playwright specs passed on the first run and the full suite (62) plus `pnpm check` stayed green.<br>• Reusing existing pieces (`adjustTime`, the `guess`/undo pattern in `optimistic.ts`, `Button` outline variant, `failureToast`) kept the UI step to one new file and small edits. |
| **Problems** | • The plan assumed only sleeps need an earliest bound. Baby Buddy also refuses to stop an overlapping feeding, so the decisions table and step 2 wording were corrected.<br>• Clicking the backdrop in Playwright hits the popup card at its centre; the spec taps a corner (`position: { x: 8, y: 8 }`). |
| **Learnings** | • A start exactly at the previous entry's end is accepted, so the earliest bound is inclusive (recorded in `../implan-molly/NOTES.md`).<br>• `steppedStart` never moves a start the opposite way to the step when it's already outside [earliest, now] (clock skew, or an entry logged after the timer started); `startSteps` derives button state from `steppedStart` so the two can't drift.<br>• RN `Modal` (transparent) was used for the popup rather than an absolute overlay, because the hero sits inside the scrolling `Screen`.<br>• Added beyond the plan: "Tap outside to save" hint, a backdrop labelled "Save and close", "Already stopped" toast on 404, and the timer button disabled while busy or while the timer is still a guess (id < 0). |
| **Risks** | • Visual review (both themes, web and Android) is still unchecked in `TEST_STRATEGY.md`.<br>• Android behaviour of the `Modal` popup (back button via `onRequestClose` saves, fade animation) is untested beyond install.<br>• The "+5 can't go past now" spec compares against the current minute and could flake at a minute boundary.<br>• The earliest bound comes from `useRecentEntries`; if the last entry of that kind falls outside the loaded window, no bound applies and a stop could still be refused.<br>• The installed APK also contained other uncommitted widget/theme changes; none of this work was committed yet. |
