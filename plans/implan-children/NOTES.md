# More than one child: notes

## Decisions

From the design (`Molly Children.dc.html` + `Molly Children Phone.dc.html`, the private design source):

- One child on screen at a time. Header: name + age. Avatar stack top right (shown child in front, up to two behind, at most three). Pull down on the stack past halfway → next child on release + toast "Showing Otto". Tap → Children sheet (one row per shown child with status, Manage children, Settings). One child: single avatar, no swipe, tap still opens the sheet.
- Another shown child's sleep running (and the one on screen awake) → strip under the header: "Otto is sleeping · 42m" + Switch.
- Settings: Children card first, a screen per child (Shown / Hidden, colour, nap window, bottle defaults, Vitamin D reminder). Theme, lock-screen timer and haptics stay shared ("For every child"). Hidden children stay in Baby Buddy and drop out of the stack.
- Onboarding "Which children?" replaces "Which child?": all ticked, first ticked opens first; skipped with one child. Button "Continue with 2 children" / disabled "Pick at least one".
- Colours: four hues (350, 210, 145, 75), avatar `oklch(0.86 0.07 h)` background, `oklch(0.34 0.08 h)` ink in day. Night values are for the implementer to pick in the same spirit.

Chosen while planning (2026-09-28), **not yet reviewed**; each is cheap to change before the step that builds it:

- **Widgets follow the child on screen in the app.** No per-widget child configuration (the old outline in `implan-molly/MAIN.md` wanted one); that stays a later idea. The widget draws the child's initial / name when more than one child is shown, and a widget tap acts on the child the widget drew, never on whatever the app shows at tap time.
- **Lock-screen notifications cover every shown child**: one sleep / feeding notification per child and timer, titles carry the child's name when more than one child is shown. Action taps carry the child id.
- **The Vitamin D reminder becomes per child** (switch on each child's screen, one reminder notification per child). Its rules from `../implan-vitamin-d-reminder/` are otherwise unchanged.
- **Per-child preferences are dropped on sign-out** (ids belong to one Baby Buddy). This changes the Vitamin D plan's "kept on sign-out" for that switch.
- **A child added in Baby Buddy after onboarding shows up shown**, with the next free colour and default nap window / bottle.
- **Default colour** = the child's position in Baby Buddy's list, mod 4.
- **Avatars are initials only.** Baby Buddy's `picture` is a media URL that may need a browser session, not the token; unverified, so photos are out of scope. The child screen's footer ("Name, birth date and photo come from Baby Buddy") drops "photo".
- **The other-child strip is for sleep only**, as designed (not feeding).
- **Existing single-child settings migrate**: the stored `childId`, `napWindow`, `bottle` and `vitaminDReminder` become that child's preferences.
- Markdown mental model only (no HTML companion).

## Facts from the code (2026-09-28)

See the step list in `MAIN.md` for where each is dealt with.

- Everything reads one `settings.childId` (`src/storage/types.ts`): session (`src/session/session.tsx`), query provider key `baseUrl|userId|childId` (`src/app/_layout.tsx`, so a switch today throws the persisted cache away), `useWidgetSync` key, widget refresh `session()` (`src/widget/refresh.ts`).
- Server data is already per child: every query key carries `childId` (`features/dashboard/queries.ts`, `history/queries.ts`, `days/queries.ts`, `optimistic.ts`); timers are looked up with `?child=&name=` (`packages/api/src/client.ts` `findTimer`), so two children's `molly:sleep` never collide in Baby Buddy. `Timer.child` exists in the type but is unread.
- `napWindow` and `bottle` are per device today, not per child.
- Widget intents are bare strings (`WIDGET_INTENTS`, `src/widget/model.ts`), no child. `WidgetCache` / `WidgetSnapshot` hold one child, `reminder` too.
- Notifications: fixed ids sleep 1, feeding 2, work 3, reminder 4 (`Notifier.kt` `idOf`), PendingIntent request codes `id*10+n`, swiped-away state in SharedPreferences `molly.notify` keyed by tracker, extras without child (`ActionReceiver.kt`, `notification/task.android.ts` gets only `{intent}`).
- e2e seeds one child (`e2e/seed.py`); `onboarding.spec.ts` ("asks which child") and `dashboard.spec.ts` (switch child in Settings) create a second child ad hoc in `beforeEach` and delete it after. Both specs describe behaviour this plan replaces.
- `react-native-gesture-handler` 2.32 and `react-native-reanimated` 4.5 are installed.
- Baby Buddy child fields: `id, first_name, last_name, birth_date, birth_time, slug, picture`; `birth_date` is always set (`implan-molly/NOTES.md`). Timers filter by `name`, `user`, `child`.

## Findings during implementation

Implemented 2026-09-28/29; choices made during implementation are marked **(choice)**.

- The design files couldn't be read in the implementing session. Everything was built from this plan's description of the design (`MAIN.md`, `MENTAL_MODEL.md`, the decisions above); the look review should compare against `Molly Children Phone.dc.html`.
- Step 1: `packages/core/src/children.ts`: `ageLabel`, `defaultChildPrefs`, `childPrefs`, `shownChildren`, `childOnScreen`, `nextChild`, `pickChildren`, `childStatus`, `ChildPrefs` / `ChildrenPrefs`, `DEFAULT_BOTTLE` (moved from the app's settings default). `chooseChild` now returns `{ type: 'selected', children: [child] }`.
- **(choice)** The age label on the birth date is `Born today`; days (`1 day`, `6 days`) in the first week, then weeks until the first full calendar month (so a baby born 31 Jan is `4 weeks` on 28 Feb), months in the first year, then `1 year`, `1 year 1 month`, `2 years 4 months`.
- **(choice)** If every child is somehow hidden (stored prefs, e.g. a child deleted in Baby Buddy), `shownChildren` keeps the first child shown, so the app never has nobody on screen.
- `childStatus` returns `{ sleeping, label }` so the sheet can colour the sleeping line in sleep ink.
- Step 2: `Settings.children` is `Record<childId, Partial<ChildPrefs>>`: only readable fields are stored / parsed, and `childPrefs` (core) fills the rest from the child's defaults (hue by its place in Baby Buddy's list). So "broken entries fall back to defaults per field" needs no index at parse time. Old settings (no `children` key) migrate their readable top-level `napWindow` / `bottle` / `vitaminDReminder` into `children[childId]`; once `children` exists the top-level fields are ignored (and no longer written). `DEFAULT_SETTINGS.children` is `{}`.
- Step 2: the e2e `signInAs` helper still writes the old single-child shape (`childId` + top-level `napWindow`), which now exercises the migration in every spec.
- Step 2 **(choice)**: "Session exposes shown children" is done with hooks in `src/features/children/use-children.ts` (`useChildrenOnScreen`, `useChildPrefs`, `useSetChildPrefs`, `useKeepChildOnScreen`) rather than inside `SessionProvider`, because the children list is a query and `SessionProvider` sits above the `QueryProvider`. `useKeepChildOnScreen` runs in `(main)/_layout.tsx` and moves `childId` to the first shown child when the stored one is hidden or gone; `useSetChildPrefs` also moves it at once when the child on screen is hidden. `setChild` in the session is now a stable callback.
- Step 2: code without Baby Buddy's list (widget refresh, notification sync) reads `prefsOnScreen(settings)` (`src/storage/types.ts`); only the colour default depends on the list, and none of them draws it yet (step 6 does).
- Step 2: the query provider key and persisted-cache buster are `baseUrl|userId`; the first start after this update drops the old cache once (its buster had the child id).
- Step 3: `/timers/?name=molly:sleep` without `child` lists every child's running sleep (see `implan-molly/NOTES.md`). `client.listTimers({ name })` pages like the entry lists. `features/children/queries.ts`: `useRunningSleeps()` (key `['timer', 'all', 'sleep']`, so every write's `timer` invalidation and the persisted `timer` set cover it), `runningSleepOf(timers, childId)`, and `useLastSleeps(childIds, enabled)` (key `['lastSleep', childId]`, `getLatestEntry('sleep', child)`, invalidated after writes and persisted too, so the sheet opens with statuses). The api test helpers gained `createChild` / `deleteChild` (admin, by slug).
- Step 4: child colours are `CHILD_COLOURS` in `src/theme/tokens.ts` (day from the design, night oklch(0.40 0.07 h) / oklch(0.90 0.06 h), hex-converted like the other tokens), set as `--child-N-bg` / `--child-N-ink` by `lookVariables(look, scheme, px)` for every theme; Tailwind classes `bg-child-1-bg` … `text-child-4-ink` (written out in `features/children/Avatar.tsx` so Tailwind finds them). `Text`'s own-colour check now knows `text-child-`.
- Step 4: `packages/core` gained `stackOf(shown, currentId)` (front first, wrapping, at most `STACK_SIZE` = 3) and `otherChildSleeping(shown, currentId, sleeps)` (first other shown child with a running sleep; none while the child on screen sleeps), both unit-tested.

The pan claims a downward move in the capture phase (dy > 4 px), so the stack's `Pressable` keeps taps, keyboard and screen readers; a browser still fires `click` after a mouse drag that ends on the same element, so a press right after a pull is ignored. `SLOTS` (front, then two behind up-left, smaller) and the pull interpolation are my own, since the design file couldn't be read: check them in the look review. The pull is held at its end until the next child is in front (no flash of the old order), with a 1.5 s fallback.
- Step 4 **(choice)**: the header keeps the Day / Night pill (between the name and the stack); the Settings link and the app-name header go, as planned (the app name still shows while the children load). Settings is reached through the Children sheet (Manage children › and Settings › both open it; Settings › uses the theme's word, `copy.settings`). The e2e specs that opened Settings from the header now use `openSettings(page)` in `e2e/tests/session.ts` (tap the stack, then Settings); `theme-picker.spec.ts` checks the playful "Options" in the sheet.

## Widgets pinned to a child (steps 8–10, from `Molly Children Widgets.dc.html`, 2026-09-29)

- Decided: the reminder's Later is Dismiss renamed, and the new wording (`Vitamin D` / `Not given today`, name first with several children, no Last-given line) applies with one child too.
- Pins: `molly.widget-pins` in AsyncStorage, `widgetId → childId | 'follow'` (`src/widget/pins.ts`, `parseWidgetPins` / `widgetChild` / `widgetPinChoices` in `model.ts`), dropped on `WIDGET_DELETED`. The cache keeps `snapshot` (the app's child, drawn by following widgets) plus `pinned` (one snapshot per other pinned, shown child; hidden ones aren't fetched, deleted ones are dropped after). `drawWidgets` and the task handler resolve each widget's child from its pin against the cache, so a tap acts on the child drawn.
- "Whose widget?" is `src/widget/configure.android.tsx`, registered with `registerWidgetConfigurationScreen`; every widget has `widgetFeatures: "reconfigurable"` (asks on add, long-press → pencil reconfigures on Android 12+). Its choices come from the cache's `timers` (every shown child), so it needs no network; Save refreshes (at most 6 s) and draws before closing. Button: `Add widget` for a new widget, `Save` when it already has a pin. With one shown child it closes at once (a blank frame for about a second). A widget added with the app's own "Add to home screen" button (`requestPinWidget`) isn't asked: it follows the app until reconfigured.
- Notification avatar: the small icon becomes the child's initial (a 96 px white letter bitmap, `IconCompat.createWithBitmap`), and Android draws it in a circle of the notification colour. **(choice)** That colour is `CHILD_ICON_COLOURS` (`src/theme/tokens.ts`), a mid tone oklch(0.52 0.10 h) of each child hue, over 5:1 against the white letter: the ink shade made every circle look black, and the pastel one can't carry a white letter. The group header keeps the app icon. Timers get a sort key (newest start first); on the emulator the newest timer sits on top.
