# Retro

## 2026-09-28: Days plan steps 1–5 (one-page swipe, Days screen, date_max on notes)

| Category | Details |
|---|---|
| **Went well** | • Building `previousWindow` on top of `windowsBefore` kept it to one line, and the "always equals `windowsBefore(...)[0]`" test pinned the two together.<br>• The step order held up: core, then API, then the swipe, then the screen. Each step landed as its own green commit.<br>• Pulling the past card out into `PastWindowCard` before building Days meant the Days rows needed no new drawing code.<br>• Playwright with a seeded week found a real core bug that no unit test had covered. |
| **Problems** | • `windowsBefore` had two old bugs that the 7-day swipe also had. It ignored the running sleep when finding past bedtimes. It also looked for a day's bedtime with no upper bound, so a gap in the logs took a later day's nap or bedtime and repeated a night.<br>• The plan's assumption that `windowsBefore` over merged weeks equals one week's result only holds once bedtimes are bounded.<br>• `Start sleep` under Playwright's fixed clock gets Baby Buddy's real server time, so the invalidation spec had to cancel a seeded timer instead.<br>• The dashboard stays mounted under the stack, so "Can't reach" text shows twice. Specs need `.last()`.<br>• The prefetch-wait threshold in `day-plan.spec.ts` compares the Node test process's real clock with the browser's fixed clock, so it is fiddly: 17 days now, 20 before. |
| **Learnings** | • Rows use the fetch time (`dataUpdatedAt`) rather than `useNow`, so the per-row `likelyFor` stays memoised.<br>• `daysRows` drops only the oldest rows with nothing logged; empty windows between logged ones stay.<br>• The `All days ›` link sits inside the pager, which is `accessible` and adjustable, so TalkBack can't reach it. The pager also offers it as a custom accessibility action (`more`).<br>• The `date_max` notes filter is confirmed on Baby Buddy v2.11.0; the client passed the query through already, only the type changed.<br>• Invalidating `['days']` is belt and braces: with a staleTime of 0, the screen refetches on remount anyway. |
| **Risks** | • The look review isn't done. The live card's totals now move to a second line because `All days ›` (a 16px `TextLink`, 44px tall) takes the header slot; check it at the largest font and in every theme.<br>• The Days list isn't virtualised: every row is a full card with a Likely lane, and `Load earlier` recalculates every row. It may be slow after many weeks on a device.<br>• Bounding the bedtime changes past windows everywhere `windowsBefore` or `dayWindow`'s `nightAfter` is used. Unit and e2e tests are green, but a bedtime logged after the next morning's 07:00 is no longer a bedtime.<br>• The screen-reader row labels and the pager's `more` action were checked on web only, not with TalkBack. |
