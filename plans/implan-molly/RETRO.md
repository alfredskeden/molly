# Retro

## 2026-09-25: Redesign steps 1–6 done, step 7 (widgets) built and waiting for the device check

| Category | Details |
|---|---|
| **Went well** | • Running the notification spike first (step 1) settled the riskiest native question in one sitting: both a local Expo module and `react-native-notify-kit` worked headless from a killed process and from the lock screen, on the emulator and a physical phone.<br>• Semantic Tailwind colours over CSS variables from one `tokens.ts` (NativeWind `vars()` on the root View) themed every screen in one pass. The same hex tokens feed the widget.<br>• Pure logic in `packages/core` and `src/widget/model.ts`, test-first, kept the UI steps thin. Dashboard, toast and edit screen were mostly composition over already-tested functions.<br>• Running the full Playwright suite after every step caught every changed label, and each spec was updated in place, none deleted. The count went from 36 to 57 specs, all passing. |
| **Problems** | • The plan's "low-importance channel" assumption was wrong: Android (at least on Pixel phones) hides silent notifications on the lock screen by default, so the channel must be `IMPORTANCE_DEFAULT` with sound and vibration off.<br>• expo-router `Link` ignores NativeWind classes on native, so header links rendered in Roboto on Android. Fixed with `Link asChild` around a `Pressable`.<br>• The widget renderer crashes (`Cannot read property 'type' of null`) on a component that returns `null`. Only a plain function called inline works.<br>• Widget taps fail on the emulator with `ActivityNotFoundException` from the launcher. Not solved; being checked on a physical phone instead.<br>• A poll or focus refetch can swap "Start sleep" for "Cancel" under a finger. It made one spec flaky; the spec was made deterministic, but the race is still real for users.<br>• `.env.test` reads are blocked for the agent, so device tests needed the tokens pasted in by hand. |
| **Learnings** | • Nunito ships as one family with a file per weight on Android and web (`expo-font` `fontDefinitions`, and `FontFace` on web). The widget renderer only fakes other weights from one file, so each widget weight needs its own `fontFamily`.<br>• Parent without `delete_timer` (`parent_a`) can PATCH their own timer's start. A future start is a `validation` error with a `start` field message.<br>• Optimistic guesses must be undone on failure: with Baby Buddy down, the refetch fails too and would leave the guess on screen.<br>• Decisions taken during execution: last breast side also skips solid-food methods, not only bottles; typed-date helpers removed; sign-out keeps the theme; a widget's elapsed time is labelled with when it was measured ("30m at 09:34"). |
| **Risks** | • Step 7 is unverified on a device: widget taps, the six layout thresholds (110/220 dp are estimates of launcher cell sizes), and day/night switching without a redraw.<br>• The layout thresholds may choose the wrong layout on launchers with other cell sizes.<br>• The notification mechanism (step 8) still needs `getForegroundInfo` for expedited work on API < 31, a `deleteIntent` for swipe-dismiss, and a monochrome icon. The permission prompt is untested.<br>• Manual visual review in both themes (DoD) hasn't happened yet; only screenshots were compared with the mock.<br>• Playwright's browser runs in a different time zone from the host, so specs must format clocks in the page. |
