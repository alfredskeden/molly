# Contributing

Molly is a personal project that one family uses every day. Issues and pull requests are welcome, but there is no support promise and no roadmap beyond what's in [`plans/`](plans/README.md).

## Setup

You need Node 24+, pnpm 10 (`corepack enable`) and Docker. Android builds also need JDK 17 and the Android SDK ([`docs/android-build.md`](docs/android-build.md)).

```sh
pnpm install
pnpm bb:up && pnpm bb:seed   # a disposable Baby Buddy on :4778 with test users; keys go to e2e/.env.test
pnpm check                   # boundaries, typecheck, lint, every Vitest suite, web-bundle check
pnpm bb:down
```

`pnpm check` must pass before a pull request. `packages/api`'s tests run against the test Baby Buddy, so it has to be up.

## How the code is tested

- **`packages/core`** (pure logic, no I/O): tests first, Vitest, with `// Given`, `// When`, `// Then` comments. Start with zero, one, many, then boundaries and errors.
- **`packages/api`** (the Baby Buddy client): integration tests against the real Baby Buddy container, not mocks.
- **Screens and flows**: Playwright against the built web image (`pnpm e2e`, needs the test Baby Buddy up and seeded).
- **Looks, widgets and Android-only behaviour**: checked by hand on the emulator and a phone.

## Things that bite

[`CLAUDE.md`](CLAUDE.md) is the architecture guide (it doubles as instructions for coding agents). The ones that cost the most time:

- `packages/core` and `packages/api` must not import React, Expo or app code: the widget's headless task runs without them. `pnpm check` enforces it.
- Android-only code lives in `*.android.ts(x)` files, with a fallback of **the same extension** (`x.android.tsx` + `x.tsx`). The web bundle must never contain widget code.
- Widget files start with `'use no memo';`, or the React Compiler breaks them and they render blank.
- Add app dependencies with `npx expo install`, not `pnpm add`.
- Never edit `apps/molly/android/`: it's generated by `expo prebuild`.
- Colours are semantic classes from `src/theme/tokens.ts`, never raw colours.

## Plans

Bigger changes get a plan folder in `plans/` (see [`plans/README.md`](plans/README.md)). Committed files never hold personal details: no real children's names or birth dates, no real logs, home addresses, devices or private accounts. Use made-up examples and documentation addresses (`baby.example.com`, `192.0.2.10`).
